5. 🔐 Authentication Flow (Zoho SSO)

flowchart LR A["User clicks Login with Zoho"] --> B["GET /api/auth/zoho"] B --> C["Redirect to Zoho OAuth2"] C --> D["User authorizes"] D --> E["Callback with auth code"] E --> F["Exchange code for token"] F --> G["Fetch profile email"] G --> H{"Email in users table?"} H -->|No| I["Access Denied"] H -->|Yes| J["Issue 8h Access Token"] J --> K["Issue Refresh Token → HttpOnly cookie"] K --> L["Redirect to app with token"] L --> M["Schedule silent refresh"] style A fill:#818cf8,color:#fff style M fill:#10b981,color:#fff

Token Security Design

  • Access Token: 8-hour lifespan, stored in React state (memory only), sent via Authorization: Bearer
  • Refresh Token: 10-year lifespan, HttpOnly/Secure/SameSite=Strict cookie, SHA-256 hashed in DB
  • Token Rotation: On each refresh, old token revoked in DB, new one issued
  • Silent Refresh: Scheduled 2 minutes before access token expiry

7. 📧 Automated Email Reminder Schedule

The scheduler runs every hour via node-cron and sends tiered reminders:

Days LeftClient EmailSales Special EmailCliq Alert
≤ 30 days✅ 30-day reminder (CC: CST)—✅ Both channels
≤ 20 days✅ 20-day reminder (CC: CST)—✅ Both channels
≤ 15 days✅ 15-day reminder (CC: CST)✅ "Meet client" to CST✅ Both channels
≤ 10 days✅ 10-day reminder (CC: CST)—✅ Both channels
≤ 5 days✅ 5-day reminder (CC: CST)✅ "Meet client" to CST✅ Both channels
≤ 3 days✅ 3-day reminder (CC: CST)—✅ Both channels
< 0 (Expired)——✅ Expiry alert + Email to Admin (CC: CST)
Catch-Up Mechanism: If the server was down and missed a tier, the next run fires the email for any tier not yet sent. It also marks all larger tiers as sent to prevent duplicates.

14. 💡 Key Design Decisions

🔐 Zoho SSO (No Passwords)

Users authenticate via Zoho org account. The users table is a pre-seeded allowlist.

🍪 HttpOnly Refresh Cookies

Refresh tokens stored as HttpOnly cookies — never accessible to JS, eliminating XSS theft.

⏰ Hourly Cron with Catch-Up

Uses ≤ comparison with 'No' flags. If server was down, next run catches up without duplicates.

🗑️ Soft Delete → Trash

Renewals move to trash_renewals. Only admins can restore or permanently delete.

🧾 Zoho Books Webhook Bridge

RMT ID custom field in Zoho Books invoices creates a seamless accounting-to-RMT bridge.

📢 Dual Cliq Channels

Every event posted to both Finance (rmt) and Sales (rmtsales) channels.
